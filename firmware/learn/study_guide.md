# ESP32 智能互动重力 LED 像素屏 - 学习指南

欢迎学习这份 ESP32-IDF 固件代码！此项目巧妙融合了**底层硬件驱动、流体力学模拟（算法）、网络通信（甚至软路由 NAT）、全栈 Web 开发（局域网 HTTP），以及前沿的大语言模型 AI 接口调用**，非常值得深入研究。

以下是为您准备的阶段性循序渐进的学习建议，您可以结合代码的目录结构开展研读：

---

## 阶段一：基础组件篇（了解底层硬件是怎么跑起来的）
**目标：掌握 ESP32 是如何与外围传感器件和 LED 点阵交互的。**
- **位置**：`components/BSP/`
- **重点阅读**：
  1. **实体按键防抖 (`BSP/KEY`)**：了解基本的 GPIO（通用输入输出）是如何配置和由于机械抖动怎样进行防抖的。
  2. **姿态传感器 (`BSP/mpu6050`)**：了解 I2C 串行通信总线是如何工作的，怎样读取六轴加速度和角速度的原始寄存器数据。
  3. **LED 阵列驱动 (`BSP/RGB` 与 `espressif__led_strip`)**：了解如何利用 ESP32 的 RMT 或 SPI 外设产生精确时序来控制类似 WS2812 的单总线彩色 LED，并怎样完成 8x8（64像素）的二维坐标到内部一维缓冲区的映射变换。

---

## 阶段二：核心算法与特效引擎篇（了解水为什么会流动）
**目标：探究最吸引人的视觉效果是如何生成的，属于本项目最具有技术含量的部分。**
- **位置**：`components/Middlewares/`
- **重点阅读**：
  1. **姿态融合 (`Middlewares/GRAVITY`)**：研究刚才的 MPU6050 原始数据是如何通过滤波（例如卡尔曼滤波或互补滤波）解算为重力矢量（Gravity Vector），从而知道哪边是“地心”的。
  2. **动画效果调度基类 (`Middlewares/SIM`)**：学习项目是如何应用**状态机管理器** (`sim_manager`) 提供统一的引擎接口，进行如火焰、流水模式平滑切换且不冲突的。
  3. **流体现态与粒子 (`Middlewares/FLIP`)**：这是一个图形和物理学算法——网格流体解算。理解它是如何接收带有倾角的重力参数，通过计算网格中每一粒子的密度和压力最后转化为 RGB 颜色的（涉及矩阵和连续物理时间步 `TimeStep` 计算）。

---

## 阶段三：网络通信与局域网全栈 Web 开发篇（了解网页是怎么呈现的）
**目标：理解嵌入式 Web 服务器、路由网络分配和前端控制是如何互相协作的。**
- **位置**：`main/web_control.c`
- **重点阅读**：
  1. **热点和连网机制**：研究 `softAP` 以及 `STA` 混杂模式是如何运作的；NVS 数据区如何永久保存路由器的账号密码（`save_sta_credentials`）。
  2. **NAT中继**：查看 `lwip_napt.h` 是怎么被初始化的，借此搞懂为啥连在设备热点上还能通过 ESP32 上网。
  3. **HTTP 响应与网页服务**：观察 `s_index_html` 的字符串驻留方式。前端用了原生 HTML+CSS+JS 绘制颜色拾取器和 8x8 画板坐标数组。注意前端通过异步 Fetch 向板子发起 POST 请求控制模式（`/api/mode` 等）的交互方法。

---

## 阶段四：AI 大模型硬件联动篇（大厂级玩法）
**目标：理解“智能音箱/智能家居”中的控制流是怎么被大语言模型（LLM）接管的。**
- **位置**：`main/web_control.c` 中的 `chat_post_handler` 及前端 JS 发送部分
- **重点阅读**：
  1. **System Prompt 工程**：查看内置的前端系统词（“你是ESP32灯板内置AI...请输出严格JSON”），理解如何通过**指令边界**迫使通用大模型输出严格带有格式的 `{"reply":"", "control": {}}` 结构。
  2. **HTTPS 请求转发**：代码中使用 `esp_http_client` 与智谱的 API `open.bigmodel.cn/api/paas/v4/chat/completions` 通信，阅读它的身份鉴权配置（Bearer Token）和分块读取机制。
  3. **软硬隔离执行**：分析 `applyAiControl`（在嵌入式前端JS代码中），解析模型返回的意图和 16 进制色彩或位图，并将其转为具体硬件驱动指令执行，完成从自然语言到 `led_strip_set_pixel` 的闭环。

---

## 阶段五：全局系统统筹与任务管理 (FreeRTOS)
**目标：理解在单片机上，这些庞杂的模块是如何同时并发执行并且互不干扰的。**
- **位置**：`main/main.c`
- **重点阅读**：
  - 各个 `xTaskCreate` 和 `xTaskCreatePinnedToCore` 是如何给按键、WiFi、HTTP Server 以及物理渲染器分配了完全独立的进程生命周期，理解 FreeRTOS 的任务优先级配置逻辑以及防止看门狗饿死的释放机制（`vTaskDelay`）。

---

### 🌟 给您的学习工具建议：
1. **安装 ESP-IDF 插件**：VS Code 左侧活动栏的 Espressif 插件，使用右上角的 `ESP-IDF Build` 图标可以验证您的代码是否编译报错。
2. **多使用全局搜索工具**：例如在 `main.c` 里看到 `sim_manager_start(g_boot_mode)` 时，选中后按 `F12` 跳转到定义，看看 `Middlewares/SIM` 具体是如何在堆内存开辟任务的。
3. **串口调试法**：代码中大量预留了 `ESP_LOGI(TAG, "")` 的日志。在研读某个模块时，可以用 `ESP-IDF Monitor Device` 打开串口监听终端，看看板子在插在电脑上时实际输出的流向，能够印证你对代码生命周期的理解。
