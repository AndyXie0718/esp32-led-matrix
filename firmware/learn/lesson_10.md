# 第 10 课：火焰特效：Doom 元胞自动机

在上一课中我们拿到了受限的平滑重力数据。本课我们将分析本项目最大的视觉卖点之一：**火焰模拟（DOOM Fire）**。这并非简单的播放 GIF 动画，而是采用经典的“元胞自动机”算法实时**计算**出来的每一帧画面。

---

## 1. 什么是 DOOM Fire 算法？

1995 年的经典游戏《毁灭战士》(DOOM PS1 版) 首次展示了一种极其逼真且计算量极低的热点火焰特效。它的核心规则如下：
想象网格的每个像素都是一个“元胞”，存放着它的**热量值** (Heat)。

1.  **底部生成（火源）**：屏幕最底部的像素持续产生最大热量（白色）。
2.  **热量上升与扩散（传播）**：每个像素的热量会向上一个像素传递。
3.  **对流扰动（风势）**：在传递时，热量不仅仅是笔直上升的，而是有一定概率向左或向右偏移。
4.  **衰减降温（灰烬）**：每次热量传递时，都会随机减掉一点点热量。热量越低，颜色从白 $\to$ 黄 $\to$ 红 $\to$ 透明 渐变。

## 2. 源码解析：渲染流程

打开 [components/Middlewares/SIM/fire_sim.c](components/Middlewares/SIM/fire_sim.c)，观察在 FreeRTOS 里执行的主循环。

### (1) 重力介入：把风“吹”平
```c
// 1. 获取通过自旋锁保护的最新重力感应
gravity_xy_t g = gravity_get(); 
float gx = 0.0f;
if (g.valid) {
    // 2. 局部放大 X 轴倾角并进行软钳位
    gx = g.gx * 2.5f;
    if (gx < -2.5f) gx = -2.5f;
    if (gx > 2.5f) gx = 2.5f;
}

// 3. 推进物理世界的一个完整帧 (Time Step)
// 注意：gx 被当做“横向风向参数”传递给了算法核心
uint32_t t_ms = (uint32_t)(esp_timer_get_time() / 1000ULL);
doom_fire_step(&fire, gx, t_ms); 
```

### (2) 热量映射颜色 (Render)
物理引擎算出来的只有“热量”（例如 0~100 的数值），它如何变漂亮呢？
```c
const float* heat = doom_fire_heat(&fire);
for (int y = 0; y < H; y++) {
    for (int x = 0; x < W; x++) {
        float v = heat[y * W + x]; // 拿到这个像素的热量值
        
        // 限幅保护热量值不越界
        if (v > (float)DOOM_HEAT_MAX) v = (float)DOOM_HEAT_MAX; 

        int hv = (int)(v + 0.5f); // 取整

        // 根据热量值，从「预先算好的调色板」中取出 RGB 颜色
        rgb8_t c = s_lut[s_palette_idx][hv]; 
        
        // 调用底层接口，写入灯珠缓冲区
        uint16_t idx = s_fire_led_map[y * W + x];
        rgb_set_fast((uint32_t)idx, c.r, c.g, c.b);
    }
}
```

## 3. 性能优化：空间换时间 (LUT 查找表)

在 64 个像素里（甚至更复杂的显示面版），如果每个像素每秒都要计算 30 次浮点颜色映射，对 CPU 的负担很重。

在代码中你能看到一个叫做 `s_lut` (Look-Up Table, 查找表) 的技术：
```c
// 预先建立好的调色板，里面预先计算好了所有热度对应的实际 RGB 并应用了硬件亮度限制
static rgb8_t s_lut[PALETTE_COUNT][DOOM_HEAT_LEVELS];

// 在任务启动的第一阶段：
build_lut(0); // 把复杂的插值运算、乘法压缩等先做完并存在数组里

// 在渲染主循环时：
// 遇到像素热量，直接按索引从 s_lut 里拿颜色，彻底消灭了浮点颜色计算
rgb8_t c = s_lut[s_palette_idx][hv];
```
这是单片机开发中非常经典的**空间换时间**降维打击优化方法。

## 4. 动手实践：自定义你自己的“火焰”

1.  **调色盘修改**：在源码顶部能看到 `PAL_CLASSIC` 数组，这是热量从冷到热（0~37级别）的颜色对应表（黑$\to$红$\to$黄$\to$白）。试着改变顶部的几个颜色值（如把 `{0xff, 0xff, 0xff}` 改为 `{0x00, 0xff, 0x00}`），观察火焰的尖端是不是变成了诡异的绿色？
2.  **取消查表影响（思考）**：如果不使用 `s_lut` 机制，而是直接在渲染的双层 `for` 循环中做颜色比例换算，你觉得代码的可读性会不会降低？如果在未来升级到了 32x32 的点阵屏（1024像素），那性能会遭到什么影响？

## 本课小结
*   **元胞自动机**通过定义像素间的简单交互规则，组合涌现出了极其复杂的自然界宏观模型（火焰）。
*   将重力的 `X` 轴分量直接转化为对流模型中的**横向偏移率（风向）**，使得火焰能随板子倾斜而摇曳。
*   利用**LUT查表机制**大幅降低浮点计算量，榨干单片机的最后一滴性能。
